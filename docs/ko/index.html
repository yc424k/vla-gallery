로봇 VLA 아키텍처 갤러리

트랜스포머 이후 로봇 제어에 쓰인 VA·VLA 모델, 휴머노이드 전신 제어기, 모바일 매니퓰레이션·내비게이션 모델을 구조도 카드로 모았습니다. 카드마다 논문 링크, 백본 LLM, 액션 헤드, 학습 GPU·시간, 학습 데이터, 추론 장치·속도·메모리, 강화학습, 베이스 제어 방식을 적었습니다.

    갤러리 보기 내 장치로 쓸 수 있는 모델 내 장치로 학습할 수 있는 모델 두 모델 비교 GitHub에서 Star 주기

    페이지

    대표 구조 7선

      01 · 추론 자원

      추론에 필요한 자원

      GPU 메모리

      가중치(파라미터 × 정밀도 바이트)에 활성값·KV 캐시·이미지 토큰이 더해집니다. 보고값은 bf16 가중치 계산값과 같거나 최대 약 4 GB 큽니다.

      지연 시간

      VLM 순전파에 액션 생성이 더해집니다. 자기회귀 토큰은 토큰 수만큼(π0-FAST 청크당 약 750 ms), flow·diffusion 헤드는 디노이징 스텝 수만큼(π0 10스텝 73 ms) 걸립니다.

      제어 주파수

      액션 청크를 한 번에 내고 나눠 실행해 추론 주기보다 빠르게 제어합니다. π0는 73 ms 추론으로 최대 50 Hz, GR00T N1은 120 Hz, Helix S1은 200 Hz입니다.

      실행 위치

      로봇 탑재(Jetson·임베디드 GPU), 로봇 옆 PC(RTX 4090), 원격 서버(A100·H100), 클라우드(TPU·Gemini API)로 나뉩니다. 큰 VLM은 서버에, 빠른 제어기는 로봇에 둡니다.

      출처: 각 모델의 논문·README·모델 카드 보고값(카드의 ‘추론 메모리’). 선은 계산값이며 활성값·KV 캐시는 포함하지 않습니다.

      장치 등급별 보고된 추론 속도

      02 · 학습 자원

      학습에 필요한 자원

      사전학습 연산

      대규모 VLA 사전학습은 A100·H100 수십~수백 장으로 1~4주가 흔합니다. OpenVLA는 A100 64장으로 14일(21,500 A100-시간), GR00T N1은 약 50,000 H100-시간을 썼습니다.

      데이터 규모

      궤적 수십만~백만 개(OpenVLA 970k 궤적) 또는 텔레옵·사람 영상 수천~수만 시간(GR00T N1 8,375.7시간)입니다. 시간 단위로 밝힌 모델은 아래 표에서 ‘데이터 시간 많은 순’으로 볼 수 있습니다.

      파인튜닝

      사전학습보다 훨씬 작아 GPU 1~8장으로 하루 안쪽이 흔합니다. OpenVLA LoRA는 A100 1장으로 10~15시간이고, 공개 모델 다수는 README에 권장 GPU와 스텝 수를 적었습니다.

      비교할 때 주의

      GPU 종류(A100·H100·GB200·TPU)가 달라 GPU-시간을 그대로 견줄 수 없습니다. 장수와 기간만 밝힌 모델은 곱해서 환산했고, 산업계 모델은 대부분 학습 자원을 밝히지 않았습니다.

      출처: 각 모델의 논문·README·모델 카드. ‘명시’는 원문이 GPU·TPU-시간을 적은 값, ‘환산’은 장수 × 기간을 곱한 값입니다. 가속기 종류를 맞추지 않은 원래 단위이며, 가로축은 로그 눈금입니다.

      GPU 종류·장수·기간으로 분류

      출처: 각 모델의 논문·README·모델 카드에서 학습 GPU 종류, 장수, 학습 기간 중 하나라도 밝힌 경우만 모았습니다. 한 모델이 여러 단계(사전학습·파인튜닝 등)를 밝혔으면 단계마다 한 줄씩 적었고, 기간은 48시간 미만이면 시간, 그 이상이면 일로 적었습니다. 장수는 원문 표현(노드 × 장수 등)을 곱한 값입니다.

      모델별 학습 자원 전체 표

      03 · 메모리 계산기

      이 모델을 돌리려면 GPU 메모리가 얼마나 필요한가

      모델을 고르거나 파라미터 수를 넣으면 정밀도별 가중치 메모리를 계산하고, 보고된 실측값과 대표 장치 메모리를 함께 보여 줍니다.

      정밀도

      계산식: 가중치 메모리(GB) = 파라미터(B) × 바이트 수. 장치 메모리는 제조사 공칭값이며 Jetson은 CPU와 메모리를 공유합니다.

      04 · 내 장치

      이 장치에서 쓸 만한 속도로 도는 모델

      장치, 정밀도, 필요한 추론 속도를 고르면 메모리에 올라가고 그 속도를 낼 것으로 보이는 모델을 골라 줍니다. 토큰형 VLA는 행동 하나에 토큰 여러 개를 내야 해서 ‘토큰 속도 ÷ 행동당 토큰 수’가 추론 속도가 되고, flow·diffusion 모델은 백본 1회와 디노이징 여러 번을 더한 시간이 추론 1회입니다.

      장치 사양과 출처

      05 · 내 장치로 학습

      이 장치에서 파인튜닝할 수 있는 모델

      장치, GPU 수, 학습 방식을 고르면 GPU 메모리에 들어가는 모델과 파인튜닝 1회(1만 스텝 · 배치 32)에 걸릴 시간을 추정합니다. 학습은 가중치 말고도 기울기, 옵티마이저 상태, 활성값을 메모리에 올려야 해서 같은 모델이라도 추론보다 몇 배 큰 메모리가 필요합니다. 사전학습 가중치가 공개된 모델만 ‘학습 가능’으로 셉니다.

      전체 파인튜닝

      모든 파라미터를 AdamW와 bf16 혼합 정밀도로 학습합니다. 가중치·기울기·fp32 사본·Adam 상태로 파라미터 1B당 약 16 GB가 들고, GPU가 여러 장이면 FSDP·ZeRO-3로 나눠 담는다고 봤습니다.

      LoRA

      가중치는 bf16으로 고정하고 작은 어댑터(파라미터의 약 1%)만 학습합니다. OpenVLA는 LoRA로 A100 1장(최소 약 27 GB), π0은 RTX 4090 1장(22.5 GB 이상)에서 파인튜닝할 수 있다고 밝혔습니다.

      QLoRA (4비트)

      고정 가중치를 4비트로 양자화해 올리고 LoRA 어댑터만 학습합니다. 메모리는 가장 적지만 VLA 공식 저장소 대부분은 지원하지 않아 직접 붙여야 합니다.

      액션 헤드만

      VLM 백본을 동결하고 flow·diffusion 액션 헤드만 학습합니다. GR00T·SmolVLA·GO-1이 이 방식을 기본이나 저메모리 옵션으로 제공하며, 헤드 크기를 아는 flow·diffusion 모델만 계산합니다.

      06 · 백본 LLM

      VLA의 백본 LLM

      백본 LLM 계열이 확인된 모델만 셉니다. ‘구성’ 표시는 논문이 VLM 이름만 밝혀 그 VLM의 공개 구성에서 LLM을 적은 경우입니다.

      계열별 모델과 백본

      07 · 강화학습

      강화학습을 어디에 썼나

      ‘사용’은 모델 자체를 RL로 학습·개선한 경우, ‘일부’는 하위 제어기·RL 생성 데이터·보상·가치 모델처럼 시스템 일부에만 RL을 쓴 경우입니다. 근거는 논문·공식 블로그 문장이며, 학습 과정을 밝히지 않은 모델은 미공개로 두었습니다.

      VLA RL 사후학습

      모방학습한 VLA·정책을 RL로 한 번 더 개선합니다. 매니퓰레이션은 π*0.6(RECAP)·GR-RL·SyVLA·GEN-1, 내비게이션은 VLN-R1·ABot-N0·LightNav-0(GRPO 계열)과 VLingNav·TIC-VLA·RING·COMPASS(PPO 계열), 사족 VLA는 MoRE(오프라인 RL)가 해당합니다.

      RL 제어기 학습

      휴머노이드 전신 제어기와 사족 loco-manipulation 제어기(VBC·RoboDuet·SLIM)를 시뮬레이션에서 PPO 등으로 학습하고 학생 정책으로 증류합니다. GPU 1장으로 1~4일이 흔하고, SONIC은 GPU 128장을 썼습니다.

      RL 하위 제어기 결합

      VLA는 모방학습으로 두고 보행·전신 실행을 RL 제어기에 맡깁니다. GR00T N1.5·N1.6(Decoupled WBC), Helix·Helix 02, Ψ0, WholeBodyVLA와 보행 로봇 VLA인 QUAR-VLA·NaVILA가 해당합니다.

      데이터·보상·가치

      RL 정책이 만든 데이터로 학습하거나(π0.7, Rho-alpha, AC-DiT, CrossFormer), 보상 모델·DPO·가치 예측을 학습에 넣습니다(DYNA-1, NORA-1.5, Cosmos Policy).

      08 · 모바일 베이스

      모바일 베이스를 어떻게 움직이나

      바퀴형 모바일 매니퓰레이션

      π0·π0.5·Mobile ALOHA·BRS·AC-DiT·PanoVLA는 베이스 속도(선속도·각속도 또는 x·y·yaw)를 팔 행동과 함께 한 정책에서 직접 냅니다. MoManipVLA는 예외로, 고정 베이스용 VLA는 그대로 두고 베이스 위치를 최적화로 정합니다.

      내비게이션 VA·VLA

      대부분 상대 웨이포인트 몇 개를 내고 PD·MPC·pure pursuit 제어기가 속도 명령으로 바꿉니다(ViNT·NoMaD·NavFoM·InternVLA-N1·TrackVLA·ABot-N0). VLM 기반 모델은 VLN-CE 벤치마크 방식대로 ‘25 cm 전진·15°/30° 회전·정지’ 같은 이산 행동을 텍스트로 내는 쪽(NaVid·Uni-NaVid·StreamVLN·FutureNav)과 웨이포인트를 내는 쪽(NavFoM·InternVLA-N1·ABot-N0·LightNav-0)으로 나뉩니다.

      사족보행

      사족 모바일 매니퓰레이션은 VLA나 고수준 정책이 몸체 속도·자세 명령만 내고, 다리 관절은 시뮬레이션 RL로 학습한 보행 제어기가 맡습니다(QUAR-VLA·MoRE의 Walk These Ways, VBC, SLIM, UMI on Legs). 사족 내비게이션 모델은 대부분 웨이포인트나 속도 명령만 내고 로봇에 내장된 보행 제어기가 따라가며, NaVILA는 RL 보행 정책을 직접 학습해 붙였습니다. 모방학습 정책이 다리 관절까지 직접 내는 예는 CrossFormer(Go1) 하나입니다.

      휴머노이드 보행

      VLA는 보행 명령(vx·vy·yaw)이나 잠재 행동을 내고 RL로 학습한 전신 제어기가 다리를 움직이는 계층 구조가 표준입니다(GR00T N1.6·N1.7, WholeBodyVLA, Ψ0, OpenHLM, ω-0). Atlas LBM은 발 자세를 내서 MPC로 실행하고, Gemini Robotics 2는 별도 보행 제어기를 밝히지 않았습니다.

      칸의 숫자는 그 방식으로 그 종류의 베이스를 움직인 모델 수이고, 색이 진할수록 많습니다. 한 모델이 여러 종류를 움직이면 칸마다 셉니다. ‘기타’는 비행 로봇과 시뮬레이션에서만 베이스를 움직인 경우입니다. 분류 근거는 각 논문·공식 문서의 행동 공간 서술이며, 카드의 ‘베이스 제어’ 항목에 한 줄로 적었습니다.

      09 · 두 모델 비교

      두 모델 나란히 보기

      카드의 ‘비교 A’·‘비교 B’ 버튼이나 아래 목록으로 모델을 고르면 구조도와 사양을 나란히 놓습니다. 값이 같은 행은 흐리게 표시합니다.

      10 · 갤러리

      모델 갤러리

      분류·발표 시기·크기·백본 LLM·액션 헤드·추론 정보·논문 유무·베이스 종류로 거릅니다. 카드 위쪽의 논문 제목을 누르면 arXiv 원문이 열리고, ‘자세히’에서 태스크·데이터·학습 설정을 확인합니다.

      조건에 맞는 모델이 없습니다. 필터를 초기화해 보세요.

      표기 기준

      범위
      2024년 이후 VA·VLA 위주이고 2024년 이전 대표 모델은 ‘참고 기준’으로 넣었습니다. 모바일 매니퓰레이션·내비게이션은 GNM·ViNT·NoMaD 같은 2024년 이전 기준 모델도 해당 분류 안에 함께 두었습니다. 트랜스포머 기반 위주이며, 영향력이 큰 비트랜스포머 모델은 ‘비교용’으로 표시했습니다. 매니퓰레이션, 휴머노이드 전신 제어, 모바일 베이스 제어(모바일 매니퓰레이션·내비게이션)를 다루고 자율주행 차량 전용 모델은 뺐습니다.
      베이스 제어
      ‘고정’은 바퀴나 다리가 있어도 이 모델이 베이스를 움직이지 않는 경우, ‘시뮬 전용’은 시뮬레이션에서만 움직인 경우입니다. 제어 방식은 정책이 베이스 속도·관절을 직접 내는지, 웨이포인트·이산 행동·속도 명령을 내고 하위 제어기(PD·MPC·RL 보행 정책)가 실행하는지로 나눴습니다. 모바일 매니퓰레이션·내비게이션 모델은 2026-10-14에 추가했고, 기존 모델 중 베이스가 있는 로봇을 쓴 경우는 원문의 행동 공간으로 다시 확인했습니다.
      내 장치 추정
      ‘04 · 내 장치’와 카드의 ‘내 장치 추정’은 실측이 아니라 계산값입니다. 메모리는 가중치와 활성값 여유분으로, 속도는 메모리 대역폭과 BF16 연산 성능으로 추정했고, 실측이 있는 모델은 실측값을 장치 비율로 환산했습니다. 장치 사양은 NVIDIA 공식 자료 기준이며, 최적화 여부에 따라 실제와 2배 넘게 다를 수 있습니다.
      미공개 · 미확인
      미공개는 논문·README·모델 카드·공식 블로그 어디에도 값이 없다는 뜻이고, 미확인은 원문을 확인하지 못했다는 뜻입니다. 추정하지 않았습니다.
      (2차) · †
      (2차)는 기사·타사 논문 등 1차 출처가 아닌 값, †는 원문 대조로 확인하지 못한 값입니다.
      A/B 표기
      출처끼리 값이 다르면 둘 다 적었습니다. 예: 7B(논문)/7.5B(README).
      구성
      ‘Gemma 2B · PaliGemma 3B 구성’처럼 적힌 백본 LLM은 논문이 VLM 이름만 밝혀, 해당 VLM의 공개 구성에서 LLM을 옮긴 값입니다.
      가중치 메모리
